# 02. ハーフブリッジ (IRS2003 + 2SK4017)

Hブリッジの半分 (上下2個のMOSFET) を、ゲートドライバIC IRS2003 で駆動します。次の 03 で、これを2組にして Hブリッジにします。

> 状態: 段階 1 (MOSFET なし) まで、実機で確認済みです。段階 2 (MOSFET を実装) 以降はこれからです。確認の記録は [02-half-bridge-test.md](02-half-bridge-test.md) にあります。回路定数は設計値で、測定結果に合わせて更新します。

## 1. 概要

### 1.1 ハーフブリッジとは

上下に2個のスイッチ (MOSFET) を直列につなぎ、その間 (中点) から出力を取り出す回路です。上をONにすると中点は電源 (+12V) に、下をONにすると GND につながります。Hブリッジは、これを2組並べたものです ([01 Hブリッジの基礎](01-h-bridge-basics.md))。

この資料では、上側を**高側** (Q_H)、下側を**低側** (Q_L) と呼びます。

### 1.2 全体の構成

```
 ATtiny1604              IRS2003                 MOSFET
 (5V のロジック)         (ゲートドライバ)

   PA4 -----------------> HIN      HO --------> Q_H --+
                                                      +--> 中点 --> 負荷
   PA5 -----------------> /LIN     LO --------> Q_L --+
```

マイコンが「どちらをONにするか」を決め、ゲートドライバIC がその指示どおりに MOSFET のゲートを駆動します。

### 1.3 なぜゲートドライバICを使うか

- **電圧に余裕がない**: マイコンのピンは 5V までです。2SK4017 は 4V でもONしますが、ゲートに 10V 前後をかけるとオン抵抗が下がり、発熱が減ります。
- **高側は、電源より高い電圧が要る**: 3 章で説明します。マイコンでは作れません。
- **切り替えを速く、安全にしたい**: IC は大きな電流でゲートを素早く充放電でき、上下が同時にONにならないためのデッドタイムも内蔵しています。

### 1.4 ゴール

- 抵抗負荷をつないで、中点の電圧が、マイコンの指示どおりに 0V と 12V の間で切り替わることを、オシロで確認する
- ゲートの波形、デッドタイム、MOSFET の発熱を測って、[動作確認の記録](02-half-bridge-test.md) に書く

モーターは、03 から使います (12V の 370 サイズのギヤードモーターを予定。無負荷 0.1〜0.3A、ロック 1〜3A 程度で、2SK4017 の 5A に収まる)。540 や 775 のような大きなモーターは、この回路では扱いません。

## 3. ゲート駆動の仕組み

ブートストラップ回路が必要になる理由を、順にたどります。IRS2003 のピン名 (HO、LO、VB、VS など) は 4.1 節にあります。

### 3.1 MOSFET はスイッチとして使う

Hブリッジでの正転・逆転・ブレーキと、PWM による速度調整は、どれも MOSFET を**完全にON**にするか**完全にOFF**にするかの切り替えで実現します ([01 Hブリッジの基礎](01-h-bridge-basics.md))。

中途半端な状態を避けるのは、発熱のためです。MOSFET の発熱は、ドレイン−ソース間の電圧と、流れる電流の積です。

| 状態 | ドレイン−ソース間の電圧 | 電流 | 発熱 (1A のとき) |
|---|---|---|---|
| 完全にON | ほぼ 0V (オン抵抗 0.1Ω × 1A = 0.1V) | 流れる | 約 0.1W |
| 完全にOFF | 12V | 0 | 0 |
| 中途半端なON | 数V | 流れる | 数W |

MOSFET を完全にONにするには、**ゲートとソースの間の電圧を十分に高くする**必要があります (2SK4017 は 4V 以上、10V 前後あれば十分)。ゲートの電圧は、GND から見た値ではなく、**ソースから見た値**で効きます。

### 3.2 低側は簡単: ソースが GND に固定されている

```
 +12V ── VCC (pin1)
                       (ICの内部のスイッチ)
                    LO (pin5) ─Rg_L─ G   Q_L
                                     S ── GND
 GND ── COM (pin4) ───────────────────┘
```

低側の MOSFET のソースは GND (0V) に固定されているので、LO が High (VCC = 12V) になれば、ゲート−ソース間も 12V で、完全にONになります。LO が Low (COM = GND) になれば、0V でOFFになります。

### 3.3 高側の問題: ONにするとソースが持ち上がる

高側の MOSFET のソースは、中点 (VS) につながっています。仮に、高側のゲートに、低側と同じように GND から見て 12V をかけたとします。

| 時点 | 中点 (ソース) の電圧 | ゲート−ソース間の電圧 | MOSFET |
|---|---|---|---|
| ONにし始め | 0V | 12V − 0V = 12V | ONに向かう |
| 中点が上がる途中 | 6V | 12V − 6V = 6V | まだONに向かう |
| しきい値付近 | 9〜10V | 2〜3V | これ以上ONにならない |

ONに向かうほど中点が 12V に近づき、ゲート−ソース間の電圧が減ります。しきい値 (2SK4017 で 1.3〜2.5V) 付近まで下がると、**中途半端なONのまま止まり**、負荷には 9〜10V 程度しかかからず、MOSFET は発熱します。

高側を完全にONにするには、**ゲートを、中点 (ソース) より常に 10V 前後高く保ち続ける**必要があります。中点が 12V まで上がるので、GND から見て約 22V 以上です。電源は 12V しかないので、このままでは作れません。

### 3.4 解決策: ブートストラップ回路

次の回路で、中点より常に高い電圧を作ります。

```
 +12V ──── D_boot ────┬──── VB (pin8)
          (A → K)     │
                    C_boot
                      │
                      └──── VS (pin6)
```

- D_boot: +12V から VB へ向かう向きにだけ電流を流すダイオード (A がアノード、K がカソード)
- C_boot: VB と VS の間のコンデンサ。高側のゲートを駆動する電荷を溜める

考え方は、**中点の上に乗った電池**です。電池 (C_boot) の下側が中点 (VS) にくっついているので、中点が上がれば、上側 (VB) も一緒に上がります。高側のゲートはこの電池で駆動するので、中点の電圧に関係なく、ゲート−ソース間に一定の電圧をかけられます。電池は、次の2つの状態を繰り返して使います。

**① 低側がONのとき (充電)**

```
 +12V
  │
  ▼  D_boot   (電流が流れる向き)
  │
  ● VB = 11.5V
  │
 ─┴─ C_boot   (ここに電荷が溜まる)
 ─┬─
  │
  ● VS = 0V    ← 低側MOSFETがONで、GNDにつながっている
  │
 GND
```

VS が 0V なので、+12V から D_boot を通って、C_boot が約 11.5V に充電されます (D_boot の順方向電圧の分だけ、12V より低くなります)。

**② 高側がONのとき (使用)**

```
 +12V
  │
  ✕  D_boot   (逆向きの電圧がかかるので、電流が流れない)
  │
  ● VB = 23.5V  ← 11.5V + 12V
  │
 ─┴─ C_boot   (両端の電圧 11.5V が、そのまま保たれる)
 ─┬─
  │
  ● VS = 12V    ← 高側MOSFETがONで、+12Vにつながっている
  │
 +12V (高側MOSFETを通して)
```

C_boot は両端の電圧 (11.5V) を保ったまま持ち上がり、VB は 12V + 11.5V = 23.5V になります。D_boot は、VB から +12V への逆流を止めます。高側のゲート−ソース間には約 11.5V がかかり、完全にONのまま保たれます。

低側のONは、自分を駆動するだけでなく、高側のための C_boot を充電する役目も持っています。

### 3.5 制約: 放電するので、スイッチングを続ける

C_boot は、**低側がONになって VS が GND に下がっている間**にだけ充電されます。高側がONの間は、高側のゲートの充電 (ONにするたび。仮に 20nC)、IC 自身の消費電流 (最大 55µA)、高側のゲート−ソース間抵抗 R_gs_H (100kΩ で約 0.115mA) に電荷を取られて、電圧が下がり続けます。

このため、**高側をONにし続けることはできません。** 定期的に低側をONにして充電し直す、つまり高側と低側のスイッチングを続ける必要があります。ここから、次のことが決まります。

- **デューティの上限**: 1周期の中に、充電の時間 (低側がONの時間) を残します。このファームウェアでは上限を 90% にしています。約19.5kHz なら、1周期 約 51µs のうち、約 5µs が充電の時間です。
- **周波数と、高側をONにできる時間**: 高側を長くONにするほど、C_boot の電圧が下がります。C_boot = 1µF、R_gs_H = 100kΩ として計算すると、次のとおりです。

  | 高側をONにしている時間 | 例 | C_boot の電圧低下 |
  |---|---|---|
  | 約 46µs | PWM 約19.5kHz、デューティ 90% (このファームウェア) | 約 0.03V |
  | 約 0.9ms | PWM 1kHz、デューティ 90% | 約 0.17V |
  | 約 9ms | PWM 100Hz、デューティ 90% | 約 1.6V |
  | 約 10ms | `h` コマンドの高側パルス | 約 1.7V (11.5V → 約 9.8V) |

  周波数を下げすぎたり、高側を長くONにしたりすると、ゲート電圧が下がって、3.3 節の「中途半端なON」に近づきます。
- **起動直後は C_boot が空**です。最初に低側を一度ONにして充電してから、高側を使います。
- **C_boot が不足したときの保護がありません** (4.4 節)。不足したまま高側をONにすると、中途半端なONになって発熱するおそれがあります。

## 4. IRS2003 の性質

出典: [Infineon IRS2003 データシート (PD60269)](https://www.infineon.com/assets/row/public/documents/24/49/infineon-irs2003-datasheet-en.pdf)。Infineon は IRS2003 を新規設計に推奨していません (後継: IRS2007)。

### 4.1 ピン配置 (SOIC-8)

上から見た図で、左上の `*` が1番ピンです。

```
              IRS2003S
          +-----\_/-----+
 VCC    1 |*           | 8   VB
 HIN    2 |            | 7   HO
 /LIN   3 |            | 6   VS
 COM    4 |            | 5   LO
          +-------------+
```

| ピン | 名前 | 機能 |
|---|---|---|
| 1 | VCC | 低側とロジックの電源 (10〜20V) |
| 2 | HIN | 高側入力。**正論理** (1 で HO がON) |
| 3 | /LIN | 低側入力。**負論理** (0 で LO がON) |
| 4 | COM | 低側のリターン (GND) |
| 5 | LO | 低側ゲート出力 |
| 6 | VS | 高側のフローティング電源のリターン (= ハーフブリッジの中点) |
| 7 | HO | 高側ゲート出力 |
| 8 | VB | 高側のフローティング電源 (C_boot の+側) |

### 4.2 主な電気的特性

| 項目 | 値 |
|---|---|
| ゲート駆動電源 VCC | 10〜20V |
| VCC低電圧保護 (UVLO) | 立ち上がり 8.9V (8〜9.8V)、立ち下がり 8.2V (7.4〜9V) |
| 入力しきい値 | VIH 2.5V以上、VIL 0.8V以下 (3.3V・5Vロジックで使える) |
| 出力電流 | ソース 130mA以上、シンク 270mA以上 (パルス) |
| ターンオンの遅れ / ターンオフの遅れ | 標準 680ns / 150ns |
| 内蔵デッドタイム | 標準 520ns (400〜650ns) |
| 高側オフセット電圧 | 最大 200V |

ターンオンの遅れとターンオフの遅れの差 (680 − 150 = 530ns) は、内蔵デッドタイムとほぼ同じです。IC は、OFF はすぐに、ON はデッドタイムの分だけ遅らせて行うことで、デッドタイムを作っていると考えられます。実測では、ターンオンが 645ns、ターンオフが 114ns で、差は 531ns でした。デッドタイムの実測値 (両方向とも 532ns) とよく合います ([動作確認の記録](02-half-bridge-test.md) の 1-4)。

### 4.3 入力の動作

| HIN | /LIN | HO | LO | 状態 |
|---|---|---|---|---|
| 0 | 1 | OFF | OFF | 全OFF (待機状態) |
| 0 | 0 | OFF | ON | 低側のみON |
| 1 | 1 | ON | OFF | 高側のみON |
| 1 | 0 | — | — | 上下が同時にON の指示。IC の貫通防止ロジックが働く (使わない) |

- /LIN は反転入力なので、**HIN と /LIN に同じ信号を入れると、HO と LO は必ず逆になります (相補駆動)。** 切り替わりのたびに、内蔵デッドタイムが入ります。6 章の PWM は、この性質を使います。
- 上下が同時にONになる指示でも、貫通防止ロジックが働きます (データシート図1)。ただし、これに頼らず、ファームウェアでもこの指示を出さないようにします。

### 4.4 注意する性質

- **高側は、HIN が変化したときにだけ切り替わります。** HIN の変化は、短いパルスとして浮いた高側の回路に送られ、高側はそれをラッチ (記憶の回路) で覚えています。電源を入れた直後や、配線を誤ったあとは、HIN が変化するまで、高側が ON のまま残ることがあります ([動作確認の記録](02-half-bridge-test.md) の 1-2)。その状態で低側をONにすると、上下が同時にONになります。ファームウェアでは、低側をONにする前に HIN に短いパルスを出して、高側を OFF にそろえます (6.1 節)。
- **VB 側の低電圧保護がありません。** 低電圧保護 (UVLO) は、データシートに VCC についてだけ記載があります。C_boot が不足したまま高側をONにしても、IC は止めてくれません (3.5 節)。

## 5. 回路

### 5.1 構成

電源部 (MOSFET と負荷):

```
 +12V ---*--------------------------+
         |                          |
         |                          D
         |  HO--[Rg_H]---*--------G    Q_H
         |               |          S
         |       R_gs_H  |          |
         |               +-[100k]---*
        --- C_bus                   |
        ---                         *---- VS (6番ピン)、負荷へ
         |                          |
         |                          D
         |  LO--[Rg_L]---*--------G    Q_L
         |               |          S
         |       R_gs_L  |          |
         |               +-[10k]----*
         |                          |
 GND ----*--------------------------+
```

- Rg_H、Rg_L はゲート抵抗、R_gs_H、R_gs_L はゲートとソースの間の抵抗です (5.3 節)。
- ブートストラップ部 (D_boot、C_boot) は、3.4 節の図のとおりです。

電源とGND:

- ATtiny1604 の電源は FT232RQ モジュールの 5V、IRS2003 の VCC は +12V です。**+5V と +12V をつながないこと。**
- **GND は、ATtiny1604、IRS2003 (COM)、12V 電源のマイナス端子、FT232RQ のすべてを共通にします。** GND が共通でないと、ATtiny1604 が出す信号の基準と、IRS2003 が受け取る基準がずれて、HIN と /LIN を正しく判定できません。

GND は、次のように1点でつなぎます。

```
 12V 電源の -  ---*---- Q_L のソース、C_bus の -        (電力の GND: 太く短く)
                  |
                  +---- IRS2003 の COM                    (Q_L のソースの近く)
                  |
                  +---- ATtiny1604 の GND、FT232RQ の GND (ロジックの GND: 1本の線で)
```

負荷の電流が ATtiny1604 の GND の線や USB ケーブルを通ると、その線の抵抗で電圧が生じ、ATtiny1604 から見た GND が揺れます。それを避けるため、12V 電源のマイナス端子、Q_L のソース、C_bus の − を1か所に集め、IRS2003 の COM はそのそばに短く、ATtiny1604 と FT232RQ の GND はそこから1本の線でつなぎます。

図は概略です。**接続は、次の接続表を正とします。** (KiCad の回路図は `hardware/` に追加予定です。)

### 5.3 部品値の考え方

| 部品 | 値 | 理由 |
|---|---|---|
| ゲート抵抗 Rg_H、Rg_L | 22〜47Ω | 主な役目は、ゲート配線の振動 (リンギング) を抑えること。2SK4017 の入力容量は 730pF 程度 (販売店の仕様値。要確認) と小さく、数十Ω で十分。配線の長いブレッドボードでは 47Ω から始め、波形を見て下げる |
| R_gs_L (低側のゲート−ソース間) | 10kΩ | ドライバが駆動していない間 (電源を入れる途中など) に、ゲートを 0V に保つ。浮いたゲートが、ドレインの電圧の変化で持ち上げられて、MOSFET が勝手にONになるのを防ぐ |
| R_gs_H (高側のゲート−ソース間) | 100kΩ | 役目は R_gs_L と同じ。高側がONの間は、この電流も C_boot から出るので、大きめにする (10kΩ だと、高側 10ms のONで C_boot が空になる。3.5 節) |
| C_boot | 1µF、セラミック (X7R、耐圧 25V 以上) | ゲート電荷を仮に 20nC として、1回のONでの電圧低下を 0.5V に抑えるには 40nF 以上。IC の消費電流と R_gs_H の電流も加わるので、余裕を見て 1µF (ゲート電荷は未確認の仮定値) |
| D_boot | SBM245L (45V) | 耐圧はバス電圧 12V に対して十分。順方向電圧が小さいショットキーなので、C_boot をより高い電圧まで充電できる |
| C_vcc | 10µF + 0.1µF | IRS2003 の電源を安定させる。IC のすぐそばに置く |
| C_bus | 100µF (電解) + 0.1µF | スイッチングの瞬間の電流を MOSFET のすぐ近くから供給し、電源電圧の揺れを抑える。電解が大きな電荷を、セラミックが速い変化を受け持つ |
| プルダウン、プルアップ | 10kΩ | マイコンのリセット中や書き込み中はピンが浮く。HIN を GND へ、/LIN を +5V へ引いておくと、そのときも全OFF (HIN=0、/LIN=1) になる |
| VCC | 12V | UVLO の上側しきい値 (標準 8.9V、最大 9.8V) を十分に超える。VB は D_boot の順方向電圧の分だけ低く、約 11.5V |

### 5.4 電源を入れる順番

電源は2系統あります (ATtiny1604 は USB の 5V、IRS2003 と MOSFET は 12V)。ロジックの電源を先に入れて後に切り、マイコンが全OFF (HIN=0、/LIN=1) を出している間だけ、パワー側に電源が入っているようにします。

- **入れるとき**: USB (5V) → 12V
- **切るとき**: picocom で `o` (全OFF) → 12V → USB (5V)

先に `o` を押すのは、電流が流れていない、はっきりした状態で切るためです。モーターをつないだときは特に大切で、PWM の途中で電源を切ると、急にブレーキがかかったり、回り続けるモーターの逆起電力が電源側に戻ったりします。

逆の順番 (12V が先、または USB を先に抜く) にすると、/LIN のプルアップ先の 5V が 0V になって /LIN が 0 になり、低側がONになります。高側はOFF なので短絡はしませんが、意図しない状態なので避けます。

電源が入る途中や切れる途中の状態は、次の仕組みで守られています。

| 仕組み | 働き |
|---|---|
| IRS2003 の UVLO | VCC が約 8.9V に達するまでは、出力 (HO、LO) を出さない (この種のドライバICで一般的な動作。データシートには、しきい値以外の詳しい記述はない) |
| R_gs | IRS2003 の出力段が動いていない間も、ゲートを 0V に保つ |
| HIN のプルダウン、/LIN のプルアップ | ATtiny1604 のリセット中や書き込み中にピンが浮いても、全OFF を保つ |
| ブートストラップ | C_boot が空のうちは、高側をONにできない |

## 6. ファームウェア

[`firmware/02-half-bridge/main.c`](../firmware/02-half-bridge/main.c)

| ピン | 機能 | 接続先 |
|---|---|---|
| PA4 (2番ピン、TCA0 WO4) | HIN | IRS2003 の 2番ピン |
| PA5 (3番ピン、TCA0 WO5) | /LIN | IRS2003 の 3番ピン |
| PB2 (7番ピン)、PB3 (6番ピン) | UART (TXD、RXD) | FT232RQ (コマンドの入力と状態の表示) |
| PA2 (12番ピン) | LED: 0.5秒ごとに点滅 | ファームウェアが動いている目印 |
| PA3 (13番ピン、TCA0 WO3) | LED: ハーフブリッジの状態を明るさで示す | 全OFF: 消灯、低側のみON: 薄く点灯、高側ON: 最大、PWM: デューティと同じ明るさ |

PA3〜PA5 は、TCA0 の WO3〜WO5 の既定のピンです ([Microchip: TCA Pin Positions](https://onlinedocs.microchip.com/oxy/GUID-ACE76F82-8072-410B-AFA7-16B2BF7B4CBA-en-US-8/GUID-9E1155F0-F789-41FC-B240-9CAE98BBDC61.html))。WO3〜WO5 は TCA0 の分割モード (8bit×2) でのみ出力されるため、このファームウェアは分割モードを使います。

### 6.1 動作とコマンド

起動すると**全OFF**で止まり、UART からの1文字のコマンドを待ちます (UART の配線と picocom の使い方は [00 UART でのデバッグ](00-uart.md))。

| キー | 動作 |
|---|---|
| `o`、`0` | 全OFF |
| `l` | 低側のみON |
| `h` | 高側パルスを1回 (低側5msONで C_boot を充電 → 全OFF → 高側10msON → 全OFF) |
| `s` | 静的テストを1周 (約7秒): 全OFF 1秒 → 低側のみON 2秒 → 全OFF 1秒 → `h` と同じ高側パルスを 100ms 間隔で20回 → 全OFF 1秒 |
| `1`〜`9` | PWM (約19.5kHz)。デューティを 10%〜90% で固定 |
| `p` | PWM スイープを1往復 (10% → 90% → 10%、各1秒) |
| `?` | コマンドの一覧と、今の状態を表示 |

- **テストの実行中 (`h`、`s`、`p`) に何かキーを押すと、全OFFにして止まります。** 止めるために押したキーは、コマンドとしては実行しません。
- コマンドを受け付けるたびに、`state: PWM 50%` のように、今の状態を表示します (UART の出力は英語の ASCII)。
- 状態を切り替えるときは、必ず全OFFを挟みます。
- **低側をONにする直前に、HIN に短いパルス (約2µs) を出して、高側を OFF にそろえます** (4.4 節)。パルスの間、低側は OFF なので、短絡はしません。起動時にも1回出します。
- PWM は、HIN と /LIN に同じ波形を出して、相補駆動にします (4.3 節)。デューティは高側がONの割合で、上限 90% は C_boot を充電する時間を残すためです (3.5 節)。PWM を始める前に、低側を 5ms ONにして、C_boot を充電しておきます。

### 6.2 タイマと時間の管理

クロックは 20MHz に設定しています (既定は 20MHz/6 = 3.33MHz)。20MHz 動作には電源 4.5V 以上が必要なため、ATtiny1604 は 5V で動かします (データシートで要確認)。

| タイマ | 役割 |
|---|---|
| TCA0 (分割モード) | PWM。WO4 (PA4) が HIN、WO5 (PA5) が /LIN、WO3 (PA3) が状態表示の LED。8bit なので、20MHz を4分周して周期256にすると、約19.5kHz |
| TCB0 | 1ms ごとの割り込み。時刻 (ms) を数え、PA2 の LED を点滅させる |

**時間の管理は割り込みに任せ、`main` のループは待ち時間なしで回します。** テスト (`h`、`s`、`p`) は段階 (ステップ) に区切った状態機械で、`main` のループは、UART の受信を確かめ、「次の段階に進む時刻」になっていれば次の段階に進めます。このため、テストの実行中でもキーを受け付けて、すぐに止められます (`_delay_ms` で待つ書き方との違いは、`firmware/01-pwm-led` と `firmware/01-pwm-led-intr` を比べるとわかります)。

- 時刻は 1ms 単位なので、高側パルスの 5ms と 10ms は、実際には 1ms 未満ずれます (実測で 4.04ms など)。
- 状態を切り替えるときの 10µs の全OFF、高側をそろえる 2µs のパルス、PWM を始める前の 5ms の充電は、`_delay_us` と `_delay_ms` で待っています。
- 分割モードのコンペアレジスタにはバッファがなく、書くとすぐ反映されます。HIN と /LIN を1つずつ書き換える一瞬に、HIN の High が /LIN の High より長くなると、上下が同時にONになる指示が出ます。そのため、デューティを上げるときは /LIN を先に、下げるときは HIN を先に書き換えています。

### 6.3 書き込みと実行

FT232RQ を書き込み (UPDI) の配線にして書き込み、RXD と TXD のケーブルを UART の配線に差し替えて、picocom でつなぎます。`?` を押すと、コマンドの一覧が出ます。

```sh
docker exec avr-builder-dev make -C firmware/02-half-bridge flash PORT=/host-dev/ttyUSB0
picocom -b 115200 /dev/ttyUSB0
```
